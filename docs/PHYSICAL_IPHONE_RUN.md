# Run Unuttuğum Screenshotlar on your physical iPhone

This repository is `<repo>`. The iOS app ID remains **com.example.screenshotCehennemi**, deployment target **15.5**, existing project team **<TEAM_ID>** (ownership unverified), version/build **1.1.0+2**. Nothing in this guide uninstalls the app or clears its data. Make a restorable backup before updating an already installed development build. Do not let Xcode or a test runner uninstall it to “fix” provisioning; a new bundle ID is a different installation.

1. Connect the unlocked iPhone to this Mac with a data-capable cable. Tap **Trust This Computer** on iPhone and enter its passcode when prompted. In Finder, select the phone and approve Trust if shown. Keep it unlocked during first pairing.
2. Open Xcode → Window → Devices and Simulators → Devices. Select your iPhone and let Xcode finish preparing the device/support files. Use a compatible Xcode/iOS combination; this Mac has Xcode 26.3. Resolve Xcode's specific pairing/runtime messages rather than erasing the device.
3. On iPhone, Settings → Privacy & Security → **Developer Mode** → enable, restart, then confirm after unlocking if requested. The entry may appear after pairing with Xcode. If managed restrictions disallow it, ask the device administrator; the app cannot bypass them. [Apple Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device).
4. On the Mac run `open ios/Runner.xcworkspace` from this project. Xcode → Settings → Accounts: add YOUR legitimate Apple account manually. Runner target → Signing & Capabilities → confirm exact bundle ID **com.example.screenshotCehennemi**, choose its legitimate owning team and provisioning. Sign in with Apple is declared in Runner/Runner.entitlements; enable it for that exact App ID in the paid developer account and regenerate profiles. No Apple account configuration was changed automatically. Do not change the bundle ID simply to bypass an ownership/signing failure.
5. Prepare optional auth/billing with MANUAL_AUTH_AND_SERVICE_SETUP.md. Public configuration goes in ignored `config/release.public.json`; run `python3 tool/configure_auth.py config/release.public.json` for the matching Google callback. Without configuration, guest imports/OCR/library/manual organization still work; Google/Apple buttons and store sales are unavailable. Never add private Apple `.p8`, service-account JSON or RevenueCat secret keys to this client.
6. Discover the actual phone ID with `$HOME/flutter/bin/flutter devices`. From this project, install an AOT build using `$HOME/flutter/bin/flutter run --release -d YOUR_DEVICE_ID --dart-define-from-file=config/release.public.json`. For guest-only testing without that file, omit `--dart-define-from-file=...`. Alternatively use `--profile` for profiling. Replace YOUR_DEVICE_ID with the connected phone's returned ID; it is not a fabricated value. Never pass uninstall/erase/reset commands. If signing fails, resolve legitimate profiles/ownership in Xcode. Unsigned compilation cannot install an app on an iPhone.
7. Launch the installed build while connected once. Verify exact Turkish branding, complete onboarding and choose access/picker deliberately. Test local save/reopen, denied/limited/full access and Settings return. Real Google/Apple and purchases additionally require their provider configuration, an internet connection, legitimate Apple capability and sandbox setup. Tests in `integration_test` belong on a NEW dedicated simulator, not the user's phone; use `tool/test_ios_safely.sh`.
8. Stop the Flutter command with `q` (do not uninstall), unplug the cable, and launch **Unuttuğum Screenshotlar** from the iPhone Home Screen. Release/profile builds contain compiled code; the Mac may be off. Prefer Release for this check. A debug/JIT build can depend on a development launch/debugger and is not the right unattended installation. The provisioning profile must remain valid.

## What works without the Mac/internet

Manual entries, viewing/editing/deleting local collections, search/Daily Review, selected system-picker imports of locally available images, local Apple Vision OCR/classification and authorized screenshot discovery **while the app is active** work on the phone. Discovery reconciles again when returning to the app; no always-running background service or push notification capability was added. iCloud-only assets may need the phone to obtain them before this app can read them. They are not uploaded by this app.

First Google/Apple sign-in, fresh reauthorization/deletion, account refresh, store purchase/restore/entitlement verification and external links need internet as appropriate. Losing connectivity does not erase local content. Recently signed/active Pro information is bounded by known expiry and the 72-hour offline window. Signing into an account does not upload or restore a screenshot library; there is no cloud collection backup.

## Personal Team versus paid enrollment

An Apple account/Personal Team can allow limited temporary local testing when the app ID is available to that team and all requested capabilities are supported. The current Sign in with Apple entitlement is not a capability to assume works with a Personal Team. Do not remove it from the production configuration or rename this installed app's ID to make account tests appear successful. A separately reviewed guest-only per-build signing override can be used by an experienced developer for local-only testing, but would not validate Apple login or preserve another installation's identity automatically.

Apple's Personal Team profiles are short-lived (commonly seven days), with device/App ID restrictions; when the profile expires, the app may stop launching until legitimately reprovisioned from Xcode. Paid development profiles also have expiration/revocation constraints. The Mac being off is not the limitation—the app signature/provisioning lifetime is. Check the actual profile expiration in Xcode and your developer account. [Apple membership capabilities](https://developer.apple.com/help/account/basics/about-your-developer-account).

TestFlight is the appropriate repeatable distribution route once signing, App Store record, legal/privacy disclosures, auth/store configuration and real-device checks are completed. It supports installation/updates without reconnecting the Mac, but beta builds expire under Apple's TestFlight rules (currently 90 days). It requires appropriate paid developer enrollment/App Store Connect access. This task did not create a store app, enroll a team, change an Apple account, validate a signed archive or upload a build.

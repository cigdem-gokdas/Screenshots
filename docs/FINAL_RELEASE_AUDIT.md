# Unuttuğum Screenshotlar — final release audit

Audit started 21 October 2026, before implementation. This audit is scoped to this repository only. No Git repository exists here (`git status` failed), so commit/history review is unavailable. Source and the existing iPhone 17 app container were copied into a private, mode-0700 temporary backup before editing. The original simulator will not be used for integration testing. Previous preference loss on 15 October remains documented in VERIFICATION.md and cannot be retroactively repaired by this pass.

## 1. Existing architecture
Flutter 3.47.7 / Dart 3.13.5, Xcode 26.3. iOS minimum 15.5, existing bundle ID `com.example.screenshotCehennemi`, Android `com.example.screenshot_cehennemi`; unchanged package `screenshot_cehennemi`, version `1.1.0+2`, Drift schema 2. White/Manrope UI, ChangeNotifier application controller, domain models, local repository, Drift SQLite, foreground synchronization coordinator and native Apple Vision method channel.

Direct packages initially: flutter/flutter_localizations, intl, cupertino_icons, drift, drift_flutter, url_launcher, photo_manager, crypto, path_provider, path. Dev: flutter_test, integration_test, flutter_lints, drift_dev, build_runner. The lockfile is the authoritative transitive inventory. No accounts/authentication, server/API, remote AI provider/model, analytics, crash reporting, push notifications, deep links, subscription SDK, environment-key loader or CI/CD was present. No secrets/tokens need secure storage in the existing design. Preference rows contain language/sync configuration, not entitlements or credentials.

## 2. Existing data flow
`Photos screenshot subtype → bounded local thumbnail → app-private staging → Apple Vision OCR → sensitive-screen heuristic → bilingual deterministic classifier → local Drift entry + normalized screenshot copy + deduplication ledger`. No backend or AI-provider hop exists. Saved HTTP(S) links only open after a user action in an external browser. Processing uses foreground lifecycle reconciliation, not background capabilities. The existing channel is `screenshot_cehennemi/local_vision`.

## 3. Privacy risks
Screenshots/OCR can contain highly personal data. Heuristic rejection is imperfect. Full/limited Photos authorization exposes broader OS access than application filtering. There was no low-permission explicit picker path. Files and SQLite are app-private, not independently encrypted with an app-owned key; iOS file protection/backup exclusion is requested but physical-device verification remains necessary. Old backups and deleted SQLite pages may retain content. Startup sweeps temporary/orphan files; a kill can leave temporary files until restart. No server content retention exists.

## 4. Security risks
Initial findings: external links accept plain HTTP and localhost; image staging accepts unchecked names/bytes; native OCR has no independent decoded-image bounds; no per-call timeouts; native photo observation can race stop/restart; no root privacy manifest; no deploy CI/data-safe test runner; release Android signs with a debug key; privacy/legal links and subscription states are absent. These will be addressed where compatible. Content hashes are for deduplication, not anonymization or proof of secure deletion. A modified device/client cannot be made tamper-proof.

## 5. Cost-generating services
Initially no per-analysis API cost, backend hosting, analytics or crash service. Apple developer membership/distribution and optional future Google Play enrollment are external costs. RevenueCat/store subscription handling will add purchase-metadata processing and applicable service/commission costs; exact live pricing must be checked in the owner's dashboards. No paid cloud vision/text service will be introduced for an already local pipeline.

## 6. App Store blockers found
No subscription/store products, RevenueCat project/public key, production privacy/terms URLs/legal approval, signed Release validation, App Store Connect record/ownership confirmation for the existing development-style identifier, privacy disclosure or physical-device QA. No own privacy manifest; SDK manifests require a final built-artifact audit. Actual sandbox billing, restore, expiration/refund and real Photos/iCloud lifecycle testing require external/device actions.

## 7. Recommended fixes
Add free explicit system-picker imports before optional broader access; retain on-device processing; harden file/image/network boundaries; add RevenueCat with verified `pro` entitlement, monthly/yearly paywall and restore/manage flows; never gate saved data; add discoverable privacy/terms content and truthful SDK disclosures. Keep cloud quotas inapplicable until a paid server pipeline actually exists, rather than pretending a client counter is server enforcement. Add data-safe test tooling, CI and concrete release tasks.

## 8. Fixes actually completed
Initial audit checkpoint only. Implementation and executed verification results will be appended after changes and checks, without converting pending external work into passed checks.

## Completed implementation — current state

- Free explicit imports now use native PHPicker file representations on iOS and Android Photo Picker/system document picker. No unrestricted library permission is needed for this path. Only selected cache copies enter processing; unrelated library content is not scanned. The optional automatic path remains explicit and screenshot-subtype filtered. Its broader-access explanation includes local OCR/rules, no cloud upload, later revocation, limited access and foreground limitations.
- Selected imports are coalesced, bounded (10 images, 20 MiB encoded input, 80 million pixels, 8 MiB normalized output), normalized without original EXIF, locally classified on iOS, deduplicated, cancellation-safe and committed atomically in schema 2. Android selected images support manual organization without cloud processing or paid gates. MIME/decoded bounds are independently checked natively on iOS before full decode. Temporary picker/staging files are cleaned after attempts and on startup. App-private names reject traversal/symlinks; no native errors/OCR content are shown or logged.
- Existing SQLite filename, package/native identifiers, schema version, manual CRUD/status/search/review and stored preference keys are retained. New billing consent is stored separately; there is no local `isPro` authorization flag. `secure_delete` is enabled without claiming certified erasure. iOS protection is applied to existing local files as well as directories; Android backup/device-transfer exclusions and cleartext restrictions were added.
- RevenueCat `purchases_flutter 10.17.0` is the only new production SDK (equatable is a model dependency). Its resolved iOS stack is purchases-hybrid-common 19.14.0 / purchases-ios-spm 5.96.0. Only public SDK keys are client-configurable; optional diagnostics and automatic attribution-ID collection are off. No contact/subscriber attributes or screenshot fields are sent. Purchase history and an anonymous purchase identifier still leave the device and require disclosure. A temporary picker-package experiment was removed; final dependency/artifact inspection must show no picker SDK.
- Monthly/yearly custom paywall, consent-before-SDK, actual store-price rendering, purchase/cancel/pending/failure, coalesced store operations, restore found/empty, verified CustomerInfo mapping, updates/foreground refresh, expiry/refund/revocation, bounded offline access, Settings status/upgrade/restore/manage and legal entry points are implemented. Both signature verification status and active/expiry dates are checked. Unverified/inactive/stale data cannot grant Pro; free saved-data access remains independent. Pro gates iOS automation/history, never viewing/editing/deletion/selected import. Android Pro sales are disabled until a real Android Pro benefit exists.
- Public release configuration centralizes IDs, offering, legal URLs and policy bounds. Reserved/empty legal URLs and missing public keys prevent sales. No fake price, unlimited-AI benefit or cloud credit allowance is advertised. No cloud backend or second AI provider was added; server quotas/budget/authorization are explicitly inapplicable to the zero-cloud-call pipeline.
- Settings now provides offline privacy/terms summaries and configured hosted links. They disclose RevenueCat purchase reporting; the owner must supply approved full legal text/contact details. There are no user accounts to delete. Local entry/import-data deletion remains available; store subscriptions/legally retained purchase records are separate.
- The app privacy manifest was added to Runner resources. App-container timestamp/UserDefaults reasons, nontracking purchase/anonymous-ID declarations and SDK bundled manifests are reviewed. No ATT, ad, push, background, camera, microphone, location or photo-write permission was added. Release Android now uses environment-supplied real signing or no signing, never the debug key.
- Scoped credential-pattern scanner and pinned read-only GitHub CI were added. Data-safe native verification creates a separate simulator and forces `--no-uninstall`; no original simulator erase/uninstall is permitted. The original iPhone 17's 12 file hashes remain identical to the full pre-change backup. Its baseline had zero entries/preferences/jobs; this run does not repair the historical two-preference loss.

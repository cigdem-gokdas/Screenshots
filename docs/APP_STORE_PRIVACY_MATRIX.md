## SDK review

- Existing Drift/SQLite, photo_manager, path/path_provider, crypto, url_launcher, Flutter/localization/intl/equatable/Manrope remain. Screenshots are subtype-filtered; limited Photos access uses only exposed metadata, discarding non-screenshot types before loading. Explicit native picker remains available without broad authorization. No Photos write/delete, camera, microphone, location, background or push permission is added.
- RevenueCat purchases_flutter 10.17.0 keeps signature-status/active/expiry validation and bounded offline access, diagnostics and automatic attribution collection disabled, and no contact attributes/screenshots supplied. Product sales on Android remain disabled. Anonymous → Firebase UID uses SDK identity APIs, not a client entitlement flag.
- Added firebase_core 4.15.0 / firebase_auth 6.7.0, google_sign_in 7.2.0 (iOS 6.3.8), sign_in_with_apple 8.2.0. Firebase Auth only: no Firestore/Storage/Analytics/Crashlytics/Messaging SDK. SDK token storage is delegated, never copied into Drift. Firebase default automatic data collection is disabled before constructing Auth; provider-required identity/connection processing still exists. Auth native SDKs are registered without forcing guest login.
- SwiftPM may fetch repositories for products this app does not link; inspect final linked frameworks/manifests before asserting a runtime SDK is absent. Source dependency resolution alone is not proof of final payload. See PRODUCT_AUTH_VERIFICATION.md for executed artifact checks.

Existing timestamp C617.1 / UserDefaults CA92.1 reasons remain. SDK bundled manifests must be present and reviewed in the final **signed** archive; XML parsing is not Apple validation. Review auth operational identifiers/diagnostics against the exact SDK payload and providers' current disclosure guides.

App Store Connect → App Privacy: do not reuse the earlier Not Linked anonymous-only choice or blanket Data Not Collected. Store privacy labels and legally approved hosted policy must match the final configured services. In-app draft summaries are not legal approval.

## Actual native auth-manifest findings
Inspected resolved source manifests for Firebase iOS 12.19.0 Auth and GoogleSignIn iOS 9.2.0. Firebase Auth declares Other Diagnostic Data (not linked, Analytics) and User ID (linked, App Functionality). Google Sign-In declares Name, Email, Phone Number, Other Data, Coarse Location, User ID, Device ID and Other Usage Data, linked, for the listed functionality/analytics purposes; tracking is false. Both list UserDefaults CA92.1. These are SDK declarations, not evidence that this app requests every field or a device location permission. Our scopes are basic identity only and no phone/location API is called. There is no supported all-provider-telemetry-off guarantee here. Preserve these manifests and review the aggregate disclosure conservatively with actual configured behavior. User-facing auth/privacy copy now explicitly mentions provider service-usage/diagnostic metadata before optional sign-in. Earlier strict-local statements concern screenshot/OCR processing, not an assertion that account-provider metadata stays local.
